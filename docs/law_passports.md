# Паспорта законов наведения

Поле «Статус»: **книжный** (уравнение подтверждено источником), **приближение
стенда** (реализация похожа по идее, но не сверена с уравнением книги),
**экспериментальный** (вне рамок источников). Знак ⚠ = требует сверки с полным
текстом [Лаптева/Тищенко] (недоступен агенту). Внутренние `id` стабильны и не
меняются; русские названия — публичные (см. `docs/notation.md`).

Основной доступный источник по законам наведения — **[Гусев]** А.Н. Гусев.
«Системы управления летательными аппаратами», М.: Машиностроение, 1996, гл. 5
(сс. 94–115): §5.1 метод трёх точек, §5.2 методы спрямления, §5.3 метод
пропорционального сближения, §5.4 метод погони и прямого наведения. Для каждой
формулы указан раздел и страница. МПС с компенсацией ускорения цели (APN) и ZEM
этой книгой **не** нормируются и остаются экспериментальными.

Общие для всех законов: команда ортогональна скорости (`_perp(a, Vк)`), ограничена
по модулю `n_max·g` (`clip_accel`). Модель — кинематическая точка (см.
`docs/model_assumptions.md`).

## 1. Метод пропорционального сближения (МПС)

- **id:** `pn`
- **Русское название:** метод пропорционального сближения (МПС)
- **Семейство:** двухточечный (использует только `r`, `Vк`, `Vц`)
- **Идеальная кинематическая связь:** `ωл = (r × Vотн)/|r|²`,
  `a_н = N·(ωл × Vк)` — нормальное ускорение пропорционально угловой скорости
  линии визирования. Эквивалентно [Гусев] §5.3, ур. (5.15) `ψ̇_к = K·φ̇`
  (`K = const`), с. 102–103. У Гусева навигационный коэффициент обозначен `K`;
  в обозначениях стенда тот же безразмерный коэффициент есть **N (N ≡ K)**,
  поэтому закон записан как `ψ̇_к = N·φ̇`, а команда — через `N`.
- **Реализованная команда:** `ppn_accel()` — ровно `N·(ωл × Vк)`, проекция на ⊥
  скорости, насыщение `n_max·g`. Размерность: `рад/с · м/с = м/с²`, множителей нет.
- **Измерения:** истинные `r`, `Vк`, `Vц`.
- **Истинное состояние:** да. **Группа:** oracle.
- **Ограничения:** `n_max`, ортогональность скорости. Недостаток по книге (§5.3,
  с. 103): закон чувствителен к угловым колебаниям линии визирования (шум пеленга).
- **Источник:** [Гусев] §5.3, ур. (5.13)–(5.15), сс. 102–103.
- **Статус:** **книжный** (уравнение подтверждено).

## 2. Истинный метод пропорционального сближения (TPN)

- **id:** `tpn`
- **Русское название:** истинный метод пропорционального сближения (команда по
  нормали к линии визирования)
- **Семейство:** двухточечный (использует только `r`, `Vк`, `Vц`)
- **Идеальная связь:** `a = N·V_c·(ωл × r̂)`, где `V_c = −(r̂ · Vотн)` —
  закрывающая скорость, `r̂` — единичный вектор линии визирования: нормальное
  **ускорение** истинного пропорционального наведения по нормали **к ЛВ**
  (Зархан, Tactical Missiles Guidance, гл. 2, true proportional navigation;
  Siourinas et al., Proportional Navigation and Its Applications, 2021).
  Отличие от МПС (5.15): множитель `V_c` вместо `|Vк|` и направление ⊥ ЛВ
  вместо ⊥ `Vк` — при боковых геометриях команды расходятся.
- **Реализованная команда:** `tpn_accel()` — ровно `N·V_c·(ωл × r̂)`, затем
  стендовые проекция ⊥ `Vк` и насыщение `n_max·g`; при убегании (`V_c < 0`)
  закрывающая скорость обрезается до нуля — команда не разворачивает ракету
  «задом наперёд». Аналитика закреплена тестом `test_tpn_analytic_value_on_numbers`.
- **Измерения:** истинные `r`, `Vк`, `Vц`. **Истинное состояние:** да.
  **Группа:** oracle.
- **Ограничения:** `n_max`, ортогональность скорости. Особенность закона
  (Сиуринас и др., §на_properties): на нерастраверсной геометрии (`V_c = 0`,
  напр. ЛВ ⊥ скоростей) команда обращается в нуль — МПС там доворачивает с полной
  `|Vк|`; закреплено тестом `test_tpn_no_command_when_not_closing`.
- **Источник:** Зархан, «Tactical Missiles Guidance» (TPN, гл. 2); Siourinas
  et al. 2021. По [Гусев] гл. 5 **не** нормируется (такой формы в главе нет).
- **Статус:** **книжный** по англоязычному профильному источнику; конкретная
  страница Зархана агентом не видена, формула — каноническая постановка TPN
  во всех цитируемых изложениях (проверена тестом на числах).

## 3. МПС с компенсацией нормального ускорения цели

- **id:** `apn`
- **Русское название:** МПС с компенсацией нормального ускорения цели (международный alias APN)
- **Семейство:** двухточечный + ускорение цели
- **Идеальная связь:** классическая augmented PN `a = N·(ωл × Vк) + (N/2)·a_ц,⊥`.
- **Реализованная команда:** `apn_accel()` — `a_PPN + (N/2)·perp(a_ц, Vк)`; при
  `a_ц=0` совпадает с МПС с машинной точностью.
- **Измерения:** истинные `r`, `V`, **истинное ускорение цели** `a_ц`.
- **Истинное состояние:** да. **Группа:** oracle.
- **Ограничения:** `n_max`; добавка по ускорению цели не нормируется [Гусев] гл. 5.
- **Источник:** стандартная augmented PN в учебниках по наведению; **не** подтверждена
  ни по [Гусев], ни по [Лаптева/Тищенко].
- **Статус:** **экспериментальный** (не представлять как часть терминологии книги).

## 4. Метод погони

- **id:** `pure`
- **Русское название:** метод погони
- **Семейство:** двухточечный
- **Идеальная связь (книжная):** [Гусев] §5.4, ур. (5.16), с. 104: `ψ = φ` — вектор
  скорости аппарата постоянно направлен на цель (предельный случай МПС (5.15) при
  навигационном коэффициенте `N = 1`; у Гусева тот же коэффициент есть `K ≡ N = 1`,
  `C = 0`). В модели нет угла скольжения, поэтому «прямое наведение»
  (ориентация продольной оси на цель, с. 106) совпадает с погоней.
- **Реализованная команда:** `pure_pursuit_accel()` — `a = (r̂ − V̂к)·n_max·g`,
  насыщенный доворот вектора скорости к текущей линии визирования; неподвижная
  точка регулятора — ровно условие `ψ = φ` (5.16). Проверено тестом
  `test_pure_pursuit_aims_velocity_at_target` (доворот к ЛВ и нуль при совпадении).
- **Измерения:** истинные `r`, `Vк`. **Истинное состояние:** да. **Группа:** oracle.
- **Ограничения:** `n_max`. Недостаток по книге (с. 105): на финальном участке
  требуемые перегрузки растут и обращаются в бесконечность при `φ → 180°`
  (цель убегает вдогон); метод применим лишь против скоростных целей.
- **Источник:** [Гусев] §5.4, ур. (5.16), с. 104; ограничения — с. 105–106.
- **Статус:** **книжный** (геометрическое условие подтверждено уравнением книги);
  реализация — регулятор доворота, а не интегрирование дифференциального
  уравнения траектории (5.17)–(5.19).

## 5. Метод трёх точек (CLOS)

- **id:** `clos`
- **Русское название:** метод трёх точек (технический синоним CLOS)
- **Семейство:** трёхточечный (пуск, ракета, цель)
- **Идеальная связь (книжная):** [Гусев] §5.1, ур. (5.1), с. 95: ракета и цель
  удерживаются на одном луче от ПУ (`ψ_ц = ψ_р`); отклонение ракеты от луча —
  `h = r·sin Δψ`, ур. (5.6), с. 98. Требуемая кривизна — из (5.4), перегрузка
  `n = (V/g)·dθ/dt` — (5.5).
- **Реализованная команда:** `clos_accel()` — пропорциональный регулятор удержания
  на линии «пуск—цель» с усилением `k = gain·|Vк|/max(|r|,300)·2`; ошибка —
  перпендикулярное смещение ракеты от прямой (аналог книжного `h`). Проверено
  тестом `test_clos_holds_three_point_line` (команда гасит боковое отклонение).
- **Измерения:** абсолютные позиции пуска, ракеты, цели (истинные). **Группа:** oracle.
- **Ограничения:** `n_max`; не инвариантен к повороту сцены (задан фиксированной
  линией), инвариантен к параллельному переносу (проверено тестом). Недостаток
  метода по книге (§5.1, с. 98) — перерасход перегрузки на искривлённой траектории.
- **Источник:** [Гусев] §5.1, ур. (5.1)/(5.6), сс. 95–98.
- **Статус:** **книжный по условию** (удержание трёх точек на луче); реализация —
  регулятор по отклонению `h`, а не интегрирование системы (5.2)–(5.4). CLOS —
  технический синоним, не основное название.

## 6. МПС по измерениям ГСН

- **id:** `pn_gsn`
- **Русское название:** МПС по измерениям ГСН (сенсорная)
- **Семейство:** двухточечный
- **Идеальная связь:** та же, что у МПС, но `ωл` восстанавливается из измерений.
- **Реализованная команда:** `pn_seeker_accel()` — `a = |Vк|·N·(ω_az·ŷ + ω_el·ẑ)`
  в осях скоростной системы (`x` по скорости, `y` вправо, `z` вверх). Знак
  вертикальной команды положительный по месту и **согласован Python↔TypeScript**
  (тест паритета).
- **Измерения:** сглаженные декодированные угловые скорости `az_dot_s`, `el_dot_s`
  (после поля зрения, шумов, отказов, задержки). **Истинное состояние:** нет.
  **Группа:** сенсорная.
- **Ограничения:** `n_max`; профиль сенсора `fov_deg` (узкое поле) — показывать при
  сравнении.
- **Источник:** закон-первоисточник — МПС [Гусев] §5.3 (5.15); сенсорная реализация
  по измерениям ГСН — стенд.
- **Статус:** книжный метод в сенсорной реализации.

## 7–8. Экспериментальное МПС с переменным коэффициентом

- **id:** `pn_sched_oracle`, `pn_sched_sensor`
- **Русское название:** экспериментальное МПС с переменным коэффициентом
- **Семейство:** двухточечный, экспериментальный
- **Правило планирования (показать пользователю):**
  `N_sched = clip(N0 + k_rho·rho, N_min, N_max)`, команда — классическая
  `N_sched·(ωл × Vк)`. `rho` имеет размерность `1/с`, `k_rho` — `с`; диапазон `N`
  задаётся параметрами `pn_sched_n0/k_rho/n_min/n_max`.
- **oracle-вариант:** `rho = Vc/R` (истинная подсказка). **сенсорный:** `rho = θ̇/θ`
  из декодированного изображения.
- **Измерения:** oracle — истинные `Vc`,`R`; сенсор — декодированные угл. скорости и
  `rho`. **Группы:** oracle / сенсорная соответственно.
- **Ограничения:** `n_max`; `N_min ≤ N_sched ≤ N_max`.
- **Источник:** собственный эксперимент стенда (не путать с классическим МПС).
- **Статус:** **экспериментальный.**

## 9. Законы уклонения цели (дуэль; не законы наведения)

Активны только в режиме дуэли (`duel=true`): цель «видит» ракету — её
положение и скорость (аналог приёмника облучения на борту самолёта), — но не
ускорение и не будущее. Команда цели ортогональна `V_ц` и ограничена
`n_target·g` — та же конвенция, что у законов ракеты. Реализация —
`navedenie/evader.py`, публичные названия — `glossary.EVADER_LABEL`,
тесты — `tests/test_evader.py`. Обозначения от лица уклониста:
`s = p_ракеты − p_цели`, `v = v_ракеты − v_цели`, `V_c = −(ŝ·v)` — скорость
сближения (>0, пока ракета налетает).

### 9a. Уклон от точки встречи (`away`)
Прогноз точки наибольшего сближения при неизменных скоростях
(`t* = R/V_c`) и «полный банк» в сторону от прогнозируемого положения ракеты
в этот момент: команда ∝ перпендикулярная составляющая
`(p_ц + V_ц·t*) − (p_р + V_р·t*)`, вырожденный прогноз заменяется вектором `s`.
Игра на упреждении: уходит не от текущей линии, а от будущего прицела.

### 9b. ПН наоборот (`negpn`)
`a_ц = −N·(ω_ЛВ × V_ц)` — та же формула ПН, взятая со знаком минус: цель
доворачивает скорость против вращения линии визирования, увеличивая её
угловую скорость (ракете по ПН нужно тем больше перегрузки). Пропорционален
текущей `ω_ЛВ`, потому при почти радиальной геометрии (ω≈0) молчит — на
догонной цели этот закон не помогает; цена — постоянная работа на
насыщение контура ракеты (`n_peak`).

### 9c. Градиент наименьшего сближения (`cpa_max`)
Вектор упреждённого промаха `CPA_vec = s − (s·v̂)v̂` — смещение ракеты от цели
в момент ближайшего сближения при прямолинейном полёте.
`d(CPA²)/dv_rel = k·CPA_vec` (k>0 при сближении), а `Δv_rel = −a_ц·τ` —
значит «полный банк» вдоль `−CPA_vec` линейно растит CPA. Аналитический
максимум будущего минимального расстояния; при убегании (`s·v ≥ 0`) — ноль.

### 9d. Мозг-уклонист (`brain`)
Не формула, а нервная система: цель получает обучаемую схему — тот же
`FlyCircuit`-stub (279 нейронов, DN→L-C1→DN), что и муха-ракета, но с
зеркальным сенсором (`navedenie/evader_brain.py`): сетчатка цели смотрит на
ракету (`s = p_р − p_ц`, наблюдатель движется со скоростью `V_ц`), со своими
задержкой, шумом и потерей захвата — ускорения ракеты мозг не видит. Команда —
`circuit.accel_cmd(V_ц, n_target)` с клипом `n_target·g`; при `n_target = 0`
или потере захвата — ноль. Врождённые веса `default_W` — рефлекс «к пеленгу»
(бабочка на огонь): необученный мозг летит НА ракету и честно гибнет раньше
законов-уклонистов. Дрессируется «школой уклониста» эволюцией
(`navedenie/evader_train.py`, `/api/evader/gen`): фитнес минимизируется —
сбитой `{1000 + (fuse − t_end)}`, выжившей `{−t_end − 0.02·n_int(ракеты) +
0.002·cpa}` — три цели задачи пользователя материализованы буквально: не быть
сбитой, накрутить ракете перегрузки, выработать её время; геометрия поколения
детерминирована по seed. Веса чемпиона — `data/weights_evader.npz` через
`brain_store.get/set_evader_circuit` и `/api/evader/save`. Закон обслуживает
движок сам (`EvaderBrainSensor` в контуре `a_t`); плоский
`evader_accel("brain")` — явный `ValueError`.

**Ограничения:** `n_target` (перегрузка цели), при `n_target = 0` цель
неманёвренна. **Источник:** собственные формулы стенда (классическая задача
уклонения; книжным источником [Гусев] не нормируется). **Статус:**
**экспериментальный, не закон наведения** — это вторая сторона дуэли.

**Боевая жизнь ракеты:** в дуэли прогон ограничивается `fuse_life_s`
(условные 30 с работы маршевого двигателя). Не сбила за отведённое время —
вердикт `duel_result="evader"`, `reason="fuse_expired"`; сбила — `"missile"`.
Метрика жизни цели — `t_survived`.

## Закрыто по [Гусев] гл. 5 (ранее — «отложенное из-за недоступного текста»)

- **Метод погони** (`pure`) — подтверждён уравнением (5.16), с. 104; переименован
  из «эвристического регулятора» в книжное название (паспорт 4).
- **Метод трёх точек** (`clos`) — условие (5.1) и отклонение (5.6), сс. 95–98;
  статус повышен до «книжный по условию» (паспорт 5).
- **МПС** (`pn`) — закон пропорционального сближения (5.15), сс. 102–103 (паспорт 1).
- **Обозначения `ωл`, `N`** — книга использует `φ̇` для угловой скорости линии
  визирования и `K` для коэффициента; перенос в словарь — `docs/notation.md`.

## Остаётся нереализованным (уравнения есть в [Гусев], но законов в стенде нет)

1. **Методы спрямления** — §5.2, ур. (5.7)–(5.12), сс. 99–101: полное, половинное
   и частичное спрямление (стрельба в точку упреждения A). Уравнения доступны;
   реализация не добавлялась, чтобы не расширять набор без запроса.
2. **Метод параллельного сближения / совмещения** — отличается от МПС постановкой
   связи; по [Гусев] прямо не нормирован, требует отдельного источника.
   (Истинный МПС `tpn` — частный случай этого замечания: взят из англоязычного
   источника, паспорт 2.)
3. **APN и ZEM** — [Гусев] гл. 5 этих формул не содержит; остаются
   **экспериментальными** (паспорты 3 и примечание к `terminal_zem`), подтверждать
   их этой книгой нельзя.

Ни одно уравнение не выдаётся за взятое из книги, если страница не видена.
