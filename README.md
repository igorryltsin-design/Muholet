# МУХОЛЁТ — стенд законов наведения и сенсорных агентов

Воспроизводимый исследовательский стенд **законов наведения и сенсорных агентов**
(не физически достоверная модель реальной ракеты). Версия стенда — 2.0.0
(схема признаков v2, метрики прогона v4); версия видна в шапке интерфейса
и в `GET /api/health`.

Ракета и цель — материальные точки в трёх измерениях. Стенд честно делит
навигаторов на два сорта. **Oracle-законы** (ПН, истинная ПН, ПН с
компенсацией ускорения цели, метод погони, метод трёх точек, ПН по измерениям
ГСН, ПН с расписанием коэффициента) видят точную геометрию — это эталоны
с подсказкой. **Био-агент** — сенсорный: только изображение цели на фовеальной
сетчатке 16×16 (плотный центр, редкая периферия, поле до 165°) после шумов,
мёртвых рецепторов и задержки; пеленги, их скорости и захват декодируются
из кадра. «Коннектом» — connectome-informed rate model: проводка регионов
из реальных синапсов FlyWire, моторный выход — синтетический обучаемый readout.
Перехват ищется непрерывно (пересечение сферы БЧ внутри шага), промах —
непрерывный CPA; терминальная метрика η — угол встречи скоростей в момент
наибольшего сближения.

Принципы честности зафиксированы в самом коде: oracle-законы помечены как
эталоны с подсказкой; био-агенту недоступна истинная ω_ЛВ; долепестные строки
зоны перехвата не получают численной границы; в Монте-Карло бисекция границ
не запускается.

## Две модели движения

Полем `model` выбирается модель центра масс:

- `kinematic_legacy` — постоянный модуль скорости, ускорение только поворачивает
  вектор (на ней держатся все прежние тесты и эксперименты);
- `point_mass_3dof` — трёхстепенная физика: тяга/сопротивление/гравитация,
  атмосфера ICAO/US1976 ρ(H) (`phys_atmos`), волновой кризис Cx(M), располагаемая
  перегрузка из скоростного напора, рулевой привод звеном 1–2-го порядка.
  Параметры — с префиксом `phys_` (тяга, масса, Cx, τ привода, пределы…).

## Семейство законов

Для режима `ПН` поле `law` принимает (`navedenie/glossary.py`, единый источник
терминов вместе с `web/src/shell/labels.ts`):

| `law` | Закон |
|---|---|
| `pn` | Метод пропорциональной навигации (ПН) |
| `tpn` | Истинная ПН — команда по нормали к линии визирования, a = N·V_c·(ω_ЛВ × r̂); на лобовой геометрии почти совпадает с ПН, расходится на боковых |
| `apn` | ПН с компенсацией нормального ускорения цели (APN) |
| `pure` | Метод погони — антиэталон |
| `clos` | Метод трёх точек (CLOS) |
| `pn_gsn` | ПН по измерениям сенсорного канала ГСН |
| `pn_sched_oracle` · `pn_sched_sensor` | экспериментальная ПН с переменным навигационным коэффициентом N — по точному состоянию и по сенсорным измерениям |

Законы участвуют в сравнениях, в «Карте преимуществ» (пять эталонов),
в дуэльном стенде и в локальном расчёте в окне.

## Запуск

Требования: Python 3.11+ и Node 20+.

```bash
python -m venv .venv && .venv/bin/pip install -e ".[dev]"
cd web && npm install && cd ..
make dev   # API на 8091 + UI на 5173 одним процессом (make api / make web — по отдельности)
```

UI: http://127.0.0.1:5173 · API: http://127.0.0.1:8091/api/health

```bash
make test          # pytest: 400+ тестов, ~15 минут полным прогоном
make check-parity  # сверка фолбэка localSim (JS) с эталоном python по траекториям
```

> Порт API — именно 8091: на 8090 у части машин сидит другое приложение, из-за
> чего стенд раньше уходил в расчёт «в окне».

Публичная статика без установки — на GitHub Pages:
`https://igorryltsin-design.github.io/Muholet/`. Это тот же интерфейс, но без
python-бэкенда: пуск, сравнение законов, дуэль и локальный рой считаются «в
окне», серверные экраны (обучение, Монте-Карло, зона перехвата, отчёты) там
недоступны. Публикует фронт workflow `.github/workflows/pages.yml` (сборка с
`VITE_BASE=/Muholet/` при каждом пуше в main).

Без работающего API интерфейс не ломается: пуск, обучение и сравнение умеют
работать локально, прямо в окне браузера (та же модель, переписанная на
TypeScript — `web/src/localSim.ts`) — об этом сообщает индикатор «в окне»
в шапке. Паритет JS-фолбэка и python-эталона по траекториям проверяется
отдельной проверкой `make check-parity`.

## Что на экране

Пять рабочих пространств: **Полёт**, **Мозг**, **Рой**, **Дуэль**,
**Лаборатория** (15 экранов в пяти разделах: Обзор · Обучение · Анализ ·
Исследования · Модель).

- «Полёт»: слева 3D перехвата (X — дальность, Y — бок, Z — высота; маркер
  «точка встречи»), кадр ГСН, ввод сценария, метрики; справа облако клеток
  оптической доли, моторный декод, параметры τ / gain / FOV; снизу энергия
  слоёв VISION…MOTOR и лог. Режимы: `ПН`, `BIO-контур`, `BIO + ПН в резерве`.
- «Дуэль»: ракета против обученного уклониста — стенд один на один с серией
  повтором и вердиктом (сбита / отказ перехвата / ушла).
- Темы ночная/дневная (контраст WCAG AA), пробел — пуск из любого
  пространства, озвучка (X).

### Свободная расстановка

Пятая схема сближения — «ручная»: положение цели (X вперёд / Y вбок /
абсолютная высота) и начальные скорости обеих сторон задаются азимутами и
подъёмами (поля `free_tx/ty/talt`, `free_mhdg/mclimb`, `free_thdg/tclimb`;
`range_m` не участвует, дальность — производная). В интерфейсе — плавающая
панель «Расстановка» поверх сцены: план X–Y и профиль X–H в квантованном
масштабе 1/2/5·10ⁿ, перетаскивание цели мышью, кончики стрелок задают курсы
и подъёмы (0,5°), пресеты живут в localStorage. Цель можно тянуть прямо в 3D:
луч с плоскостью высоты цели даёт X/Y с шагом 50 м, Shift — высоту; орбита
камеры на время тяги отключается.

### Стохастика: «Разброс» и «Зона перехвата»

- «Разброс» — Monte-Carlo одного сценария (`POST /api/science/monte-carlo`):
  n прогонов, зерно `seed_start + i`, каждый тянет свои шумы ГСН, срывы
  сопровождения и отказы сетчатки. На выходе — гистограмма R_min, p_hit с 95 %
  ДИ Уилсона, СКО/медиана/P90, R_95, CEP_50, CSV по прогонам.
- «Зона перехвата» (`POST /api/science/capture-zone`) — сетка «дальность пуска ×
  постоянная перегрузка цели»: где ракета не успевает развернуться и где уже не
  достаёт. Строка с одним блоком перехвата уточняется бисекцией обеих границ
  отрезка; долепестные честно маркируются без численных границ; отсечка окном
  t_max несёт флаг `boundary_time_limited`. Вероятностный режим — «прогонов на
  ячейку» 1…25: ячейка получает p_hit с ДИ и медиану, попаданием строки правит
  большинство (p_hit ≥ 0.5); в MC-режиме бисекция не запускается. Два CSV:
  сетка и «Границы зоны».

### Рой, коэволюция, школа уклониста

- «Пустить рой» — генетический алгоритм подбирает веса биомозгов под фактический
  промах: поколение считается на сервере (`POST /api/swarm/gen`), популяция
  живёт на клиенте, валидация чемпиона по эталонному трио каждые 5 поколений
  (тики на кривой эволюции), веса лучшей биомухи переносятся в схему.
- Коэволюция «цель против мухи» — `/api/coevolve/*`. «Красная королева» —
  совместная эволюция мозг-ракеты против мозг-цели (`/api/queen/gen`,
  фоновая кампания `/api/queen/train`, ринг чемпионов `/api/queen/ring`).
- «Школа уклониста» (`/api/evader/gen`): популяция целей учится уходить от всех
  законов разом, поколение — бои «ученик × закон» с экзаменом по другой
  геометрии.

Все боевые циклы (школа, королева, ринг, серверный рой) распараллелены через
`navedenie/parallel.py` — общий пул процессов до 8 воркеров, размер задаётся
`MUHOLET_WORKERS`. Бои — чистые функции (сценарий + геномы → исход), поэтому
параллель даёт побитово тот же результат, что и последовательный счёт; под
pytest и при `MUHOLET_WORKERS<2` пул не поднимается.

### Обучение и три мозга

Мозги: **схема** (279 клеток), **полный** (4 439), **коннектом** (138 700;
обучаются только W_dn 2×128 и readout W_fx 128×10). Учитель — ПН,
дельта-правило; режимы «с нуля» и «дообучение», доводка по результату,
дистилляция «коннектом → схема», экспорт формул commands в исполняемые Python
и чистый C99 (`GET /api/brain/formula/python | /c`, проверяется компиляцией
в тестах).

> Осторожно: любое обучение через стенд (`/api/train*`, «Запустить обучение»
> в UI) тихо сохраняет веса в `data/weights_*.npz`. Догнанный мозг перезаписывает
> release — бэкапьте файл или поднимайте отдельный экземпляр.

### Озвучка: четыре мухи

Стенд говорит. Реплики — не заглушки, а планировщики поверх честной статистики
прогона, каждый в своём пространстве: пилот (мужской/женский голос), штурман
(«штруман»), **Кобра** — голос уклоняющейся стороны в дуэли (`web/src/wendy.ts`),
**Командир роя** — комментарий по метрикам поколений (`web/src/roy.ts`).
Варианты реплик детерминированы хешем сценария/поколения: один прогон звучит
одинаково, разные — по-разному. Шина речи (`web/src/voice.ts`) раздаёт один
аудиоканал по старшинству, субтитры — в DOM. Клипы — Silero в
`web/public/audio/`; генерация: `python tools/make_voice.py`.

## API

Сервер на :8091 (FastAPI) обслуживает интерфейс и скрипты. Группы маршрутов —
в коде `navedenie/app.py`; главные:

| Эндпоинт | Назначение |
|---|---|
| `POST /api/run` | полный прогон: кадры, метрики v4, N_eff по кадрам (тело — **плоский** сценарий) |
| `POST /api/brain/compare` | сценарий на всех мозгах и законах (тело **вложенное**: `{"scenario": …}`) |
| `POST /api/train/start · step · finish`, `…/evolve/*` | имитационное обучение; школа уклониста |
| `GET /api/brain/formula[/python|/c]` | формулы команд мозга, экспорт Python/C99 |
| `POST /api/brain/reset · /rebuild` | сброс к заводскому / пересоздание слоёв — **деструктивны к весам** |
| `POST /api/brain/distill · save · load · apply` | дистилляция учителя в схему |
| `GET /api/brain/ablation · /faults` | абляция зон коннектома; карта отказов сетчатки |
| `POST /api/transfer · /api/scaling` | матрица переносимости; кривая масштабируемости размеров |
| `POST /api/science/monte-carlo · capture-zone` | разброс; зона перехвата (с `n_runs` — вероятностная) |
| `POST /api/science/neff-report · neff-decomposition · law-hypotheses · closed-loop · ablation-features · photometric · speed-matrix · law-pipeline` | научный блок экрана «Закон» и матрица скоростей |
| `POST /api/map · /api/robustness` | карта преимуществ «манёвр × закон»; устойчивость к возмущениям |
| `POST /api/coevolve/start · step · reset · train_fly` | коэволюция цели и мухи |
| `POST /api/evader/gen · save` | школа уклониста: поколение боёв «ученик × закон» |
| `POST /api/queen/gen`, `GET/POST /api/queen/train`, `GET /api/queen/ring` | «Красная королева» и ринг чемпионов |
| `POST /api/swarm/gen` | поколение эволюции роя |
| `POST /api/duel` | дуэльный стенд «ракета против уклониста», серия повтором |
| `GET/POST /api/experiments[/name]` | архив экспериментов (`data/experiments`) |
| `POST /api/report/night` | автономный ночной отчёт: markdown + PNG в `data/experiments/night_<дата>/` |
| `GET /api/health · /api/glossary` | версия; русский глоссарий терминов |

## Данные и лицензии

Скрытые слои мозга «коннектом» собираются из РЕАЛЬНЫХ таблиц FlyWire FAFB v783
(Dorkenwald et al., Nature 2024; Lin et al., Nature 2024; **CC BY-NC-SA 4.0** —
некоммерческая лицензия, учитывайте при повторном использовании). Готовая
проводка — `data/circuit_v1.npz` (7,2 млн синапсов со знаком по
нейромедиатору), популяции — по опубликованным типам клеток (L1–L5, Tm/TmY,
T4/T5, LC/LPLC, ЦК, КС, DN). Пересборка: таблицы в `data/raw/` и
`.venv/bin/python tools/extract_subgraph.py` (нужны pandas+pyarrow). Без
`circuit_v1.npz` контур работает на структурной проводке из зерна. Подробности
и лицензия — `NOTICE`.

## Docker (полностью офлайн, linux/amd64)

Образ не требует интернета ни при работе, ни при сборке: python-пакеты берутся
из локальных `wheels/`, шрифты и фронт — из репозитория. В образ уже входят
`data/`-веса release-мозгов.

```bash
make web-build && make wheels   # один раз, на машине с сетью
make docker-offline             # сборка образа muholet:latest
make docker-run                 # UI и API на http://127.0.0.1:8080
```

Альтернатива — hermetic multi-stage (`make docker-image`: node-стадия делает
`npm ci` сама, нужна сеть на сборке). `docker-compose.yml` поднимает то же
самое, `data/` примонтирована томом — обученные мозги переживают перезапуск.
Порт занят? `-p 8095:8080` или правка compose. Учтите: amd64-образ на Apple
Silicon работает через Rosetta и в разы медленнее нативного запуска — для
работы на маке предпочтителен `make dev`.
